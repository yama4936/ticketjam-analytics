## 検証方法

- `npm run typecheck`、`npm run build`。
- 専用PostgreSQL `ticketjam_test` に `TEST_DATABASE_URL` を指定して `npm test`。21テスト、DBテストのスキップなし。追加の正常/異常経路は route-verification.md。
- DockerのChromiumをCDP接続し、agent-browserで実際のWeb→API→DBの画面を検証。表示データをモックへ差し替えていない。
- 公演比較から公演選択、公式券種、販売時間軸、幅390px、JavaScriptエラーなしを確認。
- `npm run backup:verify` は書込中のDBから同一スナップショットのdumpとハッシュを取得し、別DBへ復元して全publicテーブルを照合。元DBへの復元ではない。
- `npm run readiness` は実経過時間、毎時枠の欠測、失敗、取得元停止を集計して `.local/evidence/readiness.json` に記録する。

## 用途・部・券種の価格比較（2026-10-01）

ユーザー指摘を受け、公演単位の混合中央値を廃止。前物販・特典会・ライブ、公式の部・券種を区別する。
一覧は公式の部名と券種別の定価・中央値・件数を表示し、詳細の価格グラフは公式券種選択後に表示する。
価格比較対象は、現在の確認済み公式情報に一意に対応し、定価が分かる出品のみ。
原文の用途・部・明示日付が公式情報と矛盾する場合、接頭辞が一致しても除外する。
対応先が複数ある出品、部・券種が特定できない出品、複数の元値により定価が不明の券種は価格集計しない。
原観測は保持し、対応未確認の件数も一覧に残す。公式情報の訂正は読み取り時の再分類に反映される。

若葉のあ後日特典会の外部公演IDは1314480（12:00/1部）、1314514（13:40/2部）、1314515（15:20/3部）。
公式の各部の入場チケットは定価1,500円、手数料210円。3件は同名の重複登録ではなく別部である。
1部の取得元ページ内に「2部」と記載された出品があり、これも1部の価格集計から除外する。

cohorts.test.tsは、同じ接頭辞でも用途と元値が異なる3券種を分離し、別部・別日・曖昧な出品の除外、
全体中央値を返さないこと、定価不明時のグラフ用価格と分布の抑止を実DBで検証する。
