## 必須要件

| ID | 要件 | 完了の証拠 |
|---|---|---|
| R01 | ヒロインズ所属グループを設定・DBで管理し、公演を自動発見。初期は少数公演から開始し対象拡大可能 | 実ページと発見結果の照合、グループ追加操作 |
| R02 | 公演と出演グループは多対多。同じ対バン公演・出品を重複集計しない | 同一外部IDを複数グループから取得する統合テスト |
| R03 | 1時間ごとの独立ワーカー。公演発見・取得・公式情報・集計を分離。再試行・重複防止・失敗通知 | ジョブ実行履歴、失敗・再試行テスト、数日間の実稼働 |
| R04 | 取得元全体でアクセス間隔を共有。403・429・認証要求で停止・待機。回避しない | HTTPエラーと複数実行のテスト |
| R05 | 出品ID・URL・公演・券種・単価・枚数・整理番号原文・掲載状態・出典・実取得日時・予定日時・解析バージョンを保存 | 実ページとDBの照合 |
| R06 | 上書きだけでなく観測履歴・変化履歴を保持。元の観測から再分類・再集計できる | 再解析と履歴不変のテスト |
| R07 | 掲載中・成約確認・掲載終了理由不明・取得不能を区別。欠測やページ欠落で終了判定しない | 不完全取得・空一覧・失敗・終了・再掲載テスト |
| R08 | 成約は明示表示だけ。最後の掲載確認～成約観測の区間。最終出品価格と確認成約価格を分離 | 実ページ検証と状態遷移テスト |
| R09 | 初回観測と実出品日時を区別。一部販売・再出品は断定せず観測可能性を検証 | 価格・枚数変化・新旧IDの検証 |
| R10 | 整理番号原文、接頭辞、番号範囲を保存。不明・未確定・指定席を区別 | A12、B100番台、1〜50番等のテスト |
| R11 | 公式の公演日時・会場・券種・定価・先行/一般の販売開始日時を収集。手数料・ドリンク代を分離 | 公式ページと保存値の照合 |
| R12 | 公式対応づけは確認状態・出典URL・確認日時を保持。不明を推測しない | 管理画面で確認・訂正と不明表示の検証 |
| R13 | グループ・公演・券種・整理番号帯で絞込、中央値・最安値・価格分布・出品件数/枚数を表示 | 実DBを用いたAPI・ブラウザ検証 |
| R14 | 公演までの時間×価格/枚数、公式発売後の時間×価格/新規出品、整理番号帯×価格を可視化 | 計算テストとグラフ検証 |
| R15 | 成約確認の時間帯、初回観測から成約確認までの区間×価格/整理番号、定価倍率×残時間、グループ/公演/券種比較 | サンプル数・区間・不明値を含む集計と表示の検証 |
| R16 | 成約・掲載終了・値下げを別集計。各グラフに観測件数・最終更新・欠測・成約確認可否を表示 | 欠測時と正常時のブラウザ検証 |
| R17 | 公演一覧・詳細・時系列・整理番号比較・管理画面・元ページリンク | スマホ/デスクトップで操作検証 |
| R18 | 観測履歴と画面用集計を分離し索引を設計。取得元追加時にドメインと画面を流用できる | スキーマ、アダプター契約、クエリ検証 |
| R19 | Docker ComposeでWeb/API/ワーカー/DBを個別運用。再起動・永続化・バックアップと復元 | Compose稼働、コンテナ再作成、別DB復元一致 |
| R20 | 取得可能項目と限界、収集方針、運用手順、公開条件を文書化。公開準備を検証 | 取得検証記録、運用手順と到達性確認 |

## 将来拡張（今回の初期版の必須機能に含めない）

チケット内容と整理番号をその場で入力し、類似観測を根拠・件数付きで示し販売時期・価格の候補を支援する。
事前登録を必須にしない。データ不足のまま予測を作らない。
取得元追加・複数ワーカー・Python統計ワーカー・必要になった段階で履歴の月次分割。

## 採用構成

React + TypeScript + Vite、Node.js + TypeScript + Fastify、独立ワーカー、pg-boss、PostgreSQL、Docker Compose。
既存のリポジトリとホームサーバーで開発する。新しいSitesプロジェクトへの置換はしない。
既存のホームサーバーを利用する。palworld固有の公開条件は未確認のため、過去のサーバー資料と実構成を照合して公開先を決める。

## 完了判定

要件ごとに実装・検証記録を更新する。テストのみで数日間の実稼働を代替しない。
過去の観測データ・成約価格・公式価格を捏造しない。少数公演の実データから蓄積を開始する。
確認できないデータは不明として表示し、元要件が認めた成約識別可否による分岐を明示する。

## 2026-10-01のユーザー指示による表示方針の更新

Internet Archive連携、検索UI、取得回ごとの閲覧UIは今回不要。
公演・券種を選び、整理番号、価格、公式発売から購入済み確認までの時間をグラフで比較する。
購入済み確認と理由不明終了は分け、成約価格が公開されていなければ最終出品価格と明記する。
観測履歴の内部保存・再分類は継続する。上記はR13/R17の従来の検索・一覧中心の表示より優先する。
